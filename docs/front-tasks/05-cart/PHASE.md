# فاز 05 — Cart

## هدف فاز

ساخت تجربه کامل سبد خرید، هم به‌صورت صفحه مستقل و هم Drawer قابل باز شدن
از Header، به‌عنوان پل بین کشف محصول و Checkout.

## وابستگی‌ها
فاز 00، 01، 04 (چون افزودن به سبد از PDP اتفاق می‌افتد) کامل باشند.
Global State سبد خرید از فاز 00 باید آماده باشد.

## صفحات/Route های این فاز
`/cart`

## Component های این فاز

### CartDrawer (بخش 54 PRD)
در Desktop، از Header قابل باز شدن به‌صورت Drawer شامل: محصولات، تعداد،
قیمت، دکمه حذف، Total، CTA «ادامه به Checkout».

### صفحه Cart کامل (بخش 22 PRD)
شامل:
- افزایش/کاهش تعداد هر آیتم.
- حذف آیتم (با Confirmation در صورت نیاز — بخش 56).
- نمایش قیمت واحد و قیمت کل هر Item.
- نمایش تخفیف اعمال‌شده روی هر Item.
- Subtotal، هزینه ارسال، Total نهایی.
- CTA برجسته «ادامه به Checkout».

### CartItem
کامپوننت هر ردیف/کارت آیتم سبد — شامل تصویر، نام، سایز/رنگ انتخابی،
QuantitySelector، قیمت، دکمه حذف.

### Empty Cart State (بخش 22، 41 PRD)
Illustration + عنوان + توضیح کوتاه + CTA «مشاهده محصولات».

## جزئیات UX/UI
- تغییر تعداد باید بلافاصله Total را آپدیت کند (بدون نیاز به Refresh).
- حذف آیتم مهم → Confirmation Dialog (بخش 56 PRD، اگر مقدار/قیمت بالا
  باشد یا به‌صورت کلی تصمیم UX مستند شود).
- Badge تعداد آیتم در Header/Bottom Dock باید Real-time سینک باشد.
- هزینه ارسال می‌تواند بر اساس آستانه Mock (مثلاً رایگان بالای مبلغ X)
  محاسبه شود تا واقعی‌تر باشد.

## داده‌های Mock مورد نیاز
از محصولات موجود (فاز 12) چند آیتم به‌صورت پیش‌فرض در سبد Demo قرار
داده شود تا تست بصری راحت‌تر باشد (قابل حذف در دمو نهایی).

## State های Loading / Empty / Error مرتبط
- Empty State سبد خالی (بخش 41).
- Error State: خطای فرضی به‌روزرسانی سبد (بخش 42) — نمایش Toast خطا.
