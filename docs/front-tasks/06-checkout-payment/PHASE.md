# فاز 06 — Checkout & Payment

## هدف فاز

پیاده‌سازی جریان خرید نهایی به‌صورت مرحله‌ای، ساده و Mobile-first، همراه
با مدیریت آدرس و شبیه‌سازی کامل پرداخت.

## وابستگی‌ها
فاز 00، 01، 05 (Cart) کامل باشند. فاز 07 (Authentication) از نظر منطقی
باید کاربر Mock لاگین‌شده در دسترس باشد (یا Checkout مهمان طبق تصمیم UX).

## صفحات/Route های این فاز
`/checkout` (چندمرحله‌ای — می‌تواند Step-based در یک Route یا چند
Sub-route باشد)، `/checkout/payment`، `/order/success`، `/order/failed`

## مراحل Checkout (بخش 23 PRD)
1. اطلاعات ارسال
2. انتخاب آدرس
3. خلاصه سفارش
4. توضیحات سفارش
5. پرداخت

باید به‌صورت Stepper بصری و واضح نمایش داده شود (کاربر بداند در کدام
مرحله است).

## Component های این فاز

### AddressForm و AddressCard (بخش 24 PRD)
مدل Address: `id, title, province, city, postalCode, fullAddress`.
- استان و شهر باید Cascading Select باشند (ابتدا Province، سپس Cityهای
  همان Province).
- کاربر می‌تواند آدرس قبلی از Address Book انتخاب کند یا آدرس جدید
  بسازد؛ آدرس جدید باید قابل ذخیره در Address Book باشد (Checkbox
  «ذخیره این آدرس»).

### OrderSummary
خلاصه محصولات، تعداد، قیمت، تخفیف، هزینه ارسال، مبلغ نهایی — قابل
استفاده مجدد هم در Checkout هم در جزئیات سفارش (فاز 08).

### Invoice Mock (بخش 26 PRD)
شامل: شماره فاکتور، تاریخ، اطلاعات کاربر، آدرس، محصولات، تعداد، قیمت
واحد، تخفیف، جمع جزء، هزینه ارسال، مبلغ نهایی.

### Payment Mock (بخش 27 PRD)
- دکمه «پرداخت آنلاین» → انتقال به صفحه Payment Mock.
- شبیه‌سازی سه حالت: Success / Failed / Cancelled (مثلاً با یک Selector
  Mock یا تأخیر تصادفی برای دمو).
- **صفحه موفقیت**: پیام موفقیت، شماره سفارش، مبلغ، CTA «مشاهده سفارش».
- **صفحه خطا**: پیام خطا، دکمه «تلاش مجدد»، دکمه «بازگشت به Checkout».

## جزئیات UX/UI
- Checkout کاملاً Mobile-first باشد (بخش 7.1)؛ در Mobile شاید Bottom
  Dock موقتاً مخفی یا جایگزین دکمه «ادامه» شود (تصمیم مستند‌شده).
  Sticky Bar پایین صفحه برای دکمه «مرحله بعد» در هر Step پیشنهاد می‌شود.
- هر Step باید Validation مناسب داشته باشد و کاربر نتواند بدون تکمیل
  اطلاعات به مرحله بعد برود.
- حذف آدرس نیازمند Confirmation Dialog است (بخش 56).
- پس از ثبت سفارش موفق، سبد خرید باید خالی شود.

## داده‌های Mock مورد نیاز
- چند Address نمونه از قبل ذخیره‌شده برای کاربر Demo (بخش 50).
- لیست کامل استان/شهر ایران برای Cascading Select (حداقل نمونه‌ای معتبر
  و قابل توسعه).
- ساختار Order Mock برای تولید سفارش پس از پرداخت موفق.

## State های Loading / Empty / Error مرتبط
- Loading حین «پردازش پرداخت» (Skeleton یا Spinner کوتاه، شبیه واقعی).
- Error State: خطای Checkout (فیلد ناقص) و خطای پرداخت (بخش 42).
- Empty State: وقتی Address Book خالی است → فرم افزودن آدرس مستقیم باز
  شود.
