# فاز 07 — Authentication

## هدف فاز

پیاده‌سازی جریان ورود و ثبت‌نام Mock که رفتار واقعی احراز هویت را
شبیه‌سازی می‌کند، بدون اتصال به Backend واقعی.

## وابستگی‌ها
فاز 00 (Design System، Global State برای Auth Mock) کامل باشد.

## صفحات/Route های این فاز
`/login`، `/register`

## Component های این فاز

### فرم ثبت‌نام (بخش 28 PRD)
فیلدها: نام، شماره موبایل، گذرواژه، تأیید گذرواژه.
- Validation: تطابق گذرواژه و تأیید آن، فرمت صحیح شماره موبایل ایران.
- Password به‌صورت Password Input (بخش 55 — امنیت در Mock).

### فرم ورود (بخش 28 PRD)
فیلدها: شماره موبایل، گذرواژه.
- نکته مهم: شماره موبایل بعداً در پروفایل قابل ویرایش **نیست** (بخش 32) —
  این باید در تجربه ثبت‌نام/پروفایل هماهنگ لحاظ شود.
- Email اختیاری است و در Registration گرفته نمی‌شود.

### شبیه‌سازی Session (Mock)
- بعد از ورود/ثبت‌نام موفق → کاربر Mock در Global State ذخیره شود و به
  Dashboard (فاز 08) هدایت شود.
- محافظت از صفحات نیازمند ورود (مثلاً `/account/*`) با Redirect به
  `/login` در صورت عدم ورود.

## جزئیات UX/UI
- خطاهای اعتبارسنجی نزدیک به فیلد مربوطه و با پیام فارسی واضح.
- Toggle نمایش/مخفی‌سازی گذرواژه (چشم).
- Loading State روی دکمه Submit حین «ارسال» Mock.
- Toast موفقیت پس از ثبت‌نام/ورود.
- لینک متقابل بین صفحه ورود و ثبت‌نام.

## داده‌های Mock مورد نیاز
چند کاربر Mock از پیش تعریف‌شده (بخش 50) برای تست سناریوهای ورود موفق و
ناموفق (مثلاً شماره/گذرواژه اشتباه).

## State های Loading / Empty / Error مرتبط
- Error State: خطای Login (شماره یا گذرواژه اشتباه) — بخش 42.
- Loading دکمه Submit حین شبیه‌سازی درخواست.

## معیار پذیرش (Definition of Done)
- [ ] فرم ثبت‌نام با تمام فیلدها و Validation کار می‌کند.
- [ ] فرم ورود با سناریوی موفق و ناموفق قابل تست است.
- [ ] پس از ورود موفق، کاربر به Dashboard منتقل می‌شود و Header/Bottom
      Dock وضعیت «وارد شده» را نشان می‌دهد.
- [ ] صفحات حساب کاربری بدون ورود قابل دسترس نیستند (Redirect صحیح).

## چک‌لیست Desktop/Mobile
- [ ] فرم‌ها در موبایل با کیبورد مناسب (Numeric برای موبایل) و بدون
      Overflow نمایش داده می‌شوند.
- [ ] دکمه‌های Submit به‌اندازه کافی بزرگ و در دسترس لمس هستند.
