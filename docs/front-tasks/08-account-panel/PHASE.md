# فاز 08 — Account Panel (حساب کاربری)

## هدف فاز

ساخت کامل پنل کاربری شامل داشبورد، تاریخچه سفارش‌ها، جزئیات سفارش،
مدیریت آدرس‌ها، علاقه‌مندی‌ها و ویرایش اطلاعات — طبق بخش 8 (صفحات حساب
کاربری) PRD.

## وابستگی‌ها
فاز 00، 01، 06 (Checkout — برای اینکه Orderها موجود باشند)، 07
(Authentication) کامل باشند.

## صفحات/Route های این فاز
`/account` (Dashboard)، `/account/orders`، `/account/orders/[id]`،
`/account/profile`، `/account/addresses`، `/account/wishlist`

## Component ها و صفحات

### Dashboard (بخش 29 PRD)
نمایش: نام کاربر، شماره موبایل، تعداد کل سفارش‌ها، سفارش‌های جاری،
سفارش‌های تکمیل‌شده، سفارش‌های لغوشده، آخرین سفارش‌ها، آدرس پیش‌فرض،
خلاصه Wishlist. باید یک نمای کلی سریع و مفید باشد، نه فقط لیست خام.

### Order History با Tabs (بخش 30 PRD)
Tabs: همه / جاری / تحویل‌شده / لغو-مرجوع‌شده.
`OrderCard` شامل: شماره سفارش، تاریخ، مبلغ، وضعیت (Badge)، تعداد
محصولات، تصویر محصول، دکمه «مشاهده جزئیات».

### OrderStatus (Badge وضعیت — بخش 25 PRD)
وضعیت‌ها: در حال آماده‌سازی، ارسال شده، تحویل داده شده، لغو شده، مرجوع
شده — هرکدام با رنگ/آیکون Badge متمایز (از رنگ‌های Semantic، نه رنگ برند).

### جزئیات سفارش (بخش 31 PRD)
شامل: Timeline بصری و واضح وضعیت سفارش، اطلاعات ارسال، آدرس، محصولات
سفارش، قیمت‌ها، تخفیف، مبلغ نهایی، توضیحات، وضعیت فعلی.
از `OrderSummary` مشترک فاز 06 استفاده مجدد شود.

### ویرایش اطلاعات حساب (بخش 32 PRD)
کاربر می‌تواند نام، Email، Password را تغییر دهد. شماره موبایل فقط
Read-only نمایش داده شود (بدون امکان Edit).

### مدیریت آدرس‌ها (بخش 33 PRD)
از `AddressCard`/`AddressForm` فاز 06 استفاده مجدد (بدون Duplicate):
افزودن، ویرایش، حذف (با Confirmation — بخش 56)، تعیین Default.

### Wishlist (بخش 34 PRD)
`ProductGrid` از محصولات مورد علاقه + دکمه حذف از Wishlist + دکمه
افزودن به Cart مستقیم از کارت + Empty State.

## جزئیات UX/UI
- Logout باید Confirmation Dialog داشته باشد (بخش 56).
- تغییر Password باید فیلد «رمز فعلی» + «رمز جدید» + «تکرار رمز جدید»
  داشته باشد و Feedback موفقیت (Toast) نمایش دهد.
- Timeline سفارش باید مراحل طی‌شده و نشده را بصری متمایز کند (رنگ/آیکون).

## داده‌های Mock مورد نیاز
- چند سفارش Mock با وضعیت‌های مختلف (بخش 50).
- چند Address برای کاربر Demo.
- Wishlist اولیه با چند محصول برای دمو.

## State های Loading / Empty / Error مرتبط
- Order Skeleton، Profile Skeleton (بخش 40).
- Empty State: سفارش خالی، Wishlist خالی، Address خالی (بخش 41).
- Error State: خطای بارگذاری سفارش‌ها یا پروفایل (بخش 42).
