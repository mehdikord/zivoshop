# فاز 09 — Static Pages

## هدف فاز

تکمیل صفحات ثابت و اطلاعاتی سایت که برای اعتمادسازی برند و پشتیبانی
کاربر ضروری‌اند.

## وابستگی‌ها
فاز 00 و 01 کامل باشند.

## صفحات/Route های این فاز
`/about`، `/contact`، `/rules`

## Component ها و صفحات

### درباره ما (بخش 35 PRD)
شامل: معرفی Zivo، داستان برند، تاریخچه، Mission، Vision، ارزش‌های برند،
معرفی اعضای تیم، تصاویر، CTA ارتباط با ما. باید با هویت لوکس/زنانه/گرم
برند هماهنگ باشد و از محتوای واقعی و مرتبط استفاده کند (نه Placeholder).

### تماس با ما (بخش 36 PRD)
شامل: شماره تلفن، آدرس، Instagram، Telegram، WhatsApp، ساعات کاری، فرم
تماس، Map. Map می‌تواند Placeholder یا Embedded Mock UI باشد (بدون
اتصال واقعی به سرویس نقشه، مگر تصمیم دیگری گرفته شود).

### قوانین و مقررات (بخش 37 PRD)
شامل: شرایط خرید، شرایط پرداخت، شرایط ارسال، شرایط مرجوعی، حریم خصوصی،
مسئولیت کاربر، شرایط استفاده از سایت. پیشنهاد می‌شود با `Accordion`
(shadcn/ui) برای خوانایی بهتر بخش‌بندی شود.

## جزئیات UX/UI
- فرم تماس باید Validation و Toast موفقیت پس از ارسال Mock داشته باشد.
- لینک‌های شبکه‌های اجتماعی باید در تب جدید باز شوند.
- محتوای این صفحات باید طولانی اما خوانا باشد — از Typography Scale فاز
  00 برای Headingها و پاراگراف‌ها استفاده شود.

## داده‌های Mock مورد نیاز
- متن معرفی برند، اعضای تیم Mock (نام، عنوان، عکس نمونه).
- اطلاعات تماس Mock (شماره، آدرس، ساعات کاری).
- متن کامل و واقعی برای هر بخش قوانین (نه Lorem Ipsum).

## State های Loading / Empty / Error مرتبط
- Error State برای فرم تماس در صورت شکست ارسال Mock.

## معیار پذیرش (Definition of Done)
- [ ] هر سه صفحه با محتوای کامل و واقعی (نه Placeholder) ساخته شده‌اند.
- [ ] فرم تماس با Validation و Toast کار می‌کند.
- [ ] صفحه قوانین با Accordion یا ساختار خوانا بخش‌بندی شده است.
- [ ] لینک‌های Footer به این صفحات به‌درستی متصل‌اند.

## چک‌لیست Desktop/Mobile
- [ ] فرم تماس و اطلاعات در موبایل به‌صورت تک‌ستونه و خوانا نمایش داده
      می‌شود.
- [ ] Accordion قوانین در موبایل به‌راحتی با لمس باز/بسته می‌شود.
