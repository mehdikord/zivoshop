# فاز 12 — Mock Data Strategy (پیش‌نیاز فازهای محتوایی)

## هدف فاز

طراحی و تولید مجموعه کامل داده‌های Mock واقع‌گرایانه که پایه تمام
فازهای محتوایی (Homepage تا Account) است. طبق بخش 50 PRD، این داده‌ها
باید کاملاً واقع‌گرایانه و مرتبط با حوزه فروشگاه لباس زیر بانوان باشند.

## وابستگی‌ها
Typeهای فاز 00 (`types/`) باید تعریف شده باشند. این فاز باید **پیش یا
هم‌زمان** با فاز 02 (Homepage) شروع شود، چون تمام صفحات محصول‌محور به
آن وابسته‌اند.

## داده‌های مورد نیاز (بخش 50 PRD)

### محصولات (حداقل 20 عدد)
هر محصول طبق مدل بخش 16:
```
id, name, slug, category, brand, description, images[], videos[],
sizes[], colors[], price, discountPrice, discountPercent, rating,
reviewCount, reviews[], stock, status, createdAt
```
پوشش کامل سناریوها:
- برخی تخفیف‌دار، برخی بدون تخفیف.
- Ratingهای متفاوت (از پایین تا بالا).
- برخی با چند تصویر و Video، برخی فقط تصویر.
- برخی ناموجود/کم‌موجودی برای تست حالت‌های Stock.
- تنوع دسته: سوتین، شورت، ست، لباس خواب، لباس شب، بادی، گن، لوازم
  جانبی.

### دسته‌بندی‌ها (حداقل 8 عدد)
هر دسته با نام، تصویر، Slug و ارتباط با محصولات مربوطه.

### برندها (حداقل 5 عدد)
نام، لوگو، توضیح کوتاه.

### رنگ‌ها و سایزها
- سیستم رنگ با نام و کد Hex برای Swatch.
- سیستم سایز Dynamic بر اساس نوع محصول (طبق بخش 17: سوتین 55-95،
  لباس شب XS-XXL).

### Reviews
چند Review واقعی به‌ازای محصولات پرنظر، شامل نام، امتیاز، متن، تاریخ،
تصویر (اختیاری)، وضعیت خرید تأییدشده.

### سفارش‌ها (چند سفارش با وضعیت مختلف)
مدل بخش 25: شماره سفارش، کاربر، محصولات، تعداد، قیمت واحد، تخفیف، مبلغ
کل، آدرس ارسال، توضیحات، وضعیت (در حال آماده‌سازی/ارسال شده/تحویل
داده‌شده/لغو شده/مرجوع شده)، تاریخ ثبت.

### کاربران Mock (چند کاربر)
برای تست ورود/ثبت‌نام و سناریوهای مختلف حساب کاربری.

### آدرس‌ها (چند Address برای کاربر Demo)
مدل بخش 24 با پوشش چند استان/شهر مختلف برای تست Cascading Select.

## ساختار پیشنهادی فایل‌ها (پوشه `data/`)
```
data/
  products.json
  categories.json
  brands.json
  reviews.json
  orders.json
  users.json
  addresses.json
  provinces-cities.json
```

به‌همراه توابع کمکی در `lib/` برای Query کردن این داده‌ها (فیلتر، مرتب‌سازی،
جستجو) به‌شکلی که در آینده به‌راحتی با فراخوانی API واقعی جایگزین شود
(یعنی Componentها مستقیماً به فایل JSON وابسته نباشند، بلکه به یک لایه
Service/Repository — طبق اصل معماری بخش 1 PRD).

## معیار پذیرش (Definition of Done)
- [ ] حداقل 20 محصول با تمام فیلدها و تنوع لازم آماده است.
- [ ] حداقل 8 دسته‌بندی و 5 برند آماده است.
- [ ] Reviewها، سفارش‌ها، کاربران و آدرس‌ها طبق تعداد و تنوع بخش 50
      آماده‌اند.
- [ ] یک لایه Service/Repository (نه دسترسی مستقیم Component به JSON)
      برای Query داده‌ها پیاده‌سازی شده.
- [ ] تمام متن‌ها فارسی، واقع‌گرایانه و مرتبط با حوزه لباس زیر بانوان‌اند
      (بدون Lorem Ipsum یا داده بی‌ربط).

## نکته اجرایی
پیشنهاد می‌شود این فاز در دو مرحله انجام شود:
1. **نسخه اولیه سبک** (5-6 محصول، 3-4 دسته) هم‌زمان با فاز 00 برای
   شروع سریع فاز 02.
2. **نسخه کامل** (20+ محصول و کل داده‌های جانبی) قبل از شروع فاز 03،
   تا فیلتر/Sort و صفحات بعدی روی داده واقعی و کامل تست شوند.
